# المتطلبات التشغيلية

ما يحتاجه كلُّ برنامجٍ من برامج نزلاً ليعمل. تخرج هذه الورقةُ مع كل تصدير في مجلّد النسخة
(`dist/<القناة>/<الإصدار>/REQUIREMENTS.md`)، وتُحدَّث هنا.

| البرنامج | الملف | لمن |
|---|---|---|
| [نزلاً — الهاتف](#1-نزلاً--الهاتف-أندرويد) | `nuzuln-mobile-….apk` | الأستاذ وولي الأمر والطالب |
| [نزلاً · الإدارة — أندرويد](#2-نزلاً--الإدارة--أندرويد) | `nuzuln-admin-android-….apk` | المشرف ومدير المعهد على الهاتف |
| [نزلاً · الإدارة — ويندوز](#3-نزلاً--الإدارة--ويندوز) | `nuzuln-admin-desktop-…-windows.zip` | المشرف ومدير المعهد على الحاسوب |
| [الخادم واللوحة](#4-الخادم-واللوحة) | المستودع (`backend/`) | يُثبَّت مرّةً على الاستضافة أو على حاسوب المعهد |

## 1. نزلاً — الهاتف (أندرويد)

| | |
|---|---|
| النظام | **أندرويد 7.0 فما فوق** (API 24)، مبنيٌّ لأندرويد 16 (API 36) |
| المعالج | ARM 64-bit أو ARM 32-bit أو x86_64 — الملفُّ الواحد يحمل الثلاثة |
| الذاكرة | 2 غيغابايت أو أكثر يُستحسن |
| المساحة | **SIZE_MOBILE** للملف، ونحو ضعفه بعد التثبيت مع البيانات |
| الشاشة | من 360 نقطةً عرضاً فما فوق |
| الشبكة | الخادم الرئيسي `nuzuln.com` عبر الإنترنت، أو خادمٌ محلّي على الشبكة نفسها (ثلاثُ نقراتٍ على شعار شاشة البدء) |

**يعمل الأستاذ دون اتصال**: يسجّل التفقّد والتسميع على الجهاز ويُزامَن حين يعود الاتصال. ووليُّ
الأمر والطالب يقرآن من الخادم، فيحتاجان اتصالاً.

| الإذن | لماذا |
|---|---|
| الإنترنت وحالة الشبكة | الدخول والمزامنة وقراءة البيانات |
| الإشعارات (أندرويد 13+) | إشعاراتُ وليّ الأمر (الغياب، الإذن) — يُسأل عنها وليُّ الأمر وحده، ويعمل التطبيق إن رفضها |
| تثبيت التطبيقات (يُطلب عند أول تحديث) | التحديثُ من داخل التطبيق — [APP-UPDATES.md](APP-UPDATES.md) |

**الإشعاراتُ تحتاج خدمات Google Play** على الجهاز. وبدونها يعمل التطبيق كاملاً بلا إشعارات.

**التثبيت أول مرّة**: يُنقل ملفُّ APK إلى الهاتف ويُفتح، ويطلب أندرويد السماحَ بالتثبيت من مصدره
(المتصفّح أو مدير الملفات). وكلُّ تحديثٍ بعدها من داخل التطبيق.

## 2. نزلاً · الإدارة — أندرويد

| | |
|---|---|
| النظام | **أندرويد 7.0 فما فوق** (API 24) |
| المعالج | ARM 64-bit أو ARM 32-bit أو x86_64 |
| الذاكرة | 3 غيغابايت أو أكثر يُستحسن — المعهدُ كلُّه في قاعدةٍ على الجهاز |
| المساحة | **SIZE_ADMIN_ANDROID** للملف، ومساحةٌ لبيانات المعهد تزيد بعدد طلابه |
| الشاشة | من 360 نقطةً عرضاً؛ واللوحيُّ أريح |
| الشبكة | كالهاتف — ويعمل دون اتصال ويتزامن حين يعود |

الأذونات: الإنترنت، وتثبيتُ التطبيقات للتحديث من داخله. لا إشعارات ولا خدمات Google.

## 3. نزلاً · الإدارة — ويندوز

| | |
|---|---|
| النظام | **ويندوز 10 أو 11، 64-bit** |
| المعالج | x64 (Intel أو AMD) |
| الذاكرة | 4 غيغابايت أو أكثر |
| المساحة | **SIZE_DESKTOP** مضغوطاً، ونحو SIZE_DESKTOP_UNPACKED بعد فكّه، ومساحةٌ لبيانات المعهد والنسخ الاحتياطية |
| الشاشة | 1024 × 700 حدّاً أدنى للنافذة، و1366 × 768 فما فوق يُستحسن |
| الشبكة | كالهاتف — ويعمل دون اتصال |

**التثبيت**: يُفكّ الملفُّ المضغوط في مجلّدٍ يُكتب فيه — `المستندات` أو `C:\Nuzuln` مثلاً — ويُشغَّل
`nuzuln.exe`. ولا يحتاج تثبيتاً آخر: مكتباتُ Visual C++ اللازمة داخل المجلّد.

**التحديث من داخل البرنامج** يستبدل ملفّات المجلّد نفسِه. فإن كان في `Program Files` طلب ويندوز
صلاحيةَ المسؤول عند كل تحديث؛ ومجلّدٌ يملكه المستخدم يُحدَّث بلا سؤال.

قد يحذّر ويندوز (SmartScreen) عند أول تشغيل لأن البرنامج غيرُ موقَّعٍ بشهادة ناشر: «مزيد من
المعلومات» ← «تشغيل على أي حال».

## 4. الخادم واللوحة

| | |
|---|---|
| PHP | **8.3 أو 8.4** مع `pdo_mysql` (أو `pdo_sqlite`) و`mbstring` و`openssl` و`curl` و`fileinfo` و`intl` و`zip` |
| قاعدة البيانات | MySQL 8 / MariaDB 10.6 فما فوق على الاستضافة، أو SQLite على حاسوب المعهد |
| الجدولة | سطرُ cron يستدعي `php artisan schedule:run` كلَّ دقيقة — النسخُ الاحتياطي الليلي وغيره |
| الرفع | `upload_max_filesize` و`post_max_size` **100M فما فوق** — ملفّاتُ تحديث التطبيقات تُرفع من اللوحة |
| HTTPS | شهادةٌ للنطاق على الاستضافة. والخادمُ المحلّي على الشبكة يعمل بـhttp |
| الأدوات | Composer للتثبيت، وNode 20+ لبناء واجهة اللوحة مرّةً (لا يلزم على الخادم بعدها) |
| المتصفّح | أيُّ متصفّحٍ حديث (Chrome، Edge، Firefox، Safari) — على الحاسوب أو الهاتف |

التفصيلُ خطوةً خطوة في [DEPLOYMENT.md](DEPLOYMENT.md).
